## 停车场管理系统 v0.4.1 —— 公网部署的可用性修复

### 起因
用户反馈「找不到洁」（GitHub 网页上找不到设置 Secret 的入口），
截图是 DEMO.md 里那段「去设置 GitHub Secret」的说明。

### 核心决策：不再让用户手动设 Secret
GitHub 网页入口在 Settings → Security → Secrets and variables → Actions，
位置很深。改成：**没配 Secret 时工作流自动生成 16 位随机口令**，
显示在 Actions 任务摘要里。这样「忘了配 = 公网裸奔」的情况彻底消失。

同时提供 `tools/set_github_secret.py` —— 用 API 设 Secret，不用点网页。
（GitHub Secret API 需要 libsodium sealed box 加密，已封装；依赖 pynacl）

### 修掉的真 bug（重要）
**「同步地址」失败会导致服务被杀**：
step 级 `continue-on-error: true` 只是不让这步显示为失败，
**后续步骤照样被跳过** —— 包括「保持服务在线」。
结果：服务起了 5 秒 → 同步失败 → 保活被跳过 → 「清理」杀掉 gunicorn 和
cloudflared → 地址秒失效，但日志只显示同步那步失败，看不出真正后果。

修法：
- 「保持服务在线」和「清理」都加 `if: always()`
- 保活前先检查服务是否活着，不在就直接退出（避免空转 5 小时）
- `tools/sync_tunnel_url.py` 重写成纯 Python，所有错误内部吞掉、永远 exit 0
  （原来的 shell 拼法容易 exit 1，把 job 弄红）
- 加 `concurrency: {group: parking-deploy, cancel-in-progress: true}`
  —— 之前多个 run 能同时跑，tunnel-url.txt 被后一个覆盖，地址和实际跑着的对不上

### 另一个改进：地址和口令写回仓库
Actions 任务摘要要登录才能看。新增两个文件：
- `tunnel-url.txt` —— 只有公网地址，一行，给脚本 curl 用
- `tunnel-info.txt` —— 地址 + 口令 + 说明，给人看

不用登录 GitHub 就能拿到全部信息（仓库是公开的，等于「知道地址就知道口令」，
能挡误扫的路人，挡不住有心人；要更严就自己配 ACCESS_PWD Secret）。

### 环境相关的坑（这台机器）
- **GCM（Git 凭据管理器）的浏览器 OAuth 流程极不可靠**：
  `git credential fill` 会卡住等浏览器，且 token 不落盘到 Windows 凭据管理器
  （cmdkey /list 里查不到）。用户网络不好时基本取不到 token。
  → 结论：**别依赖 GCM token**，改走 SSH 推送 + 推 tag 触发部署。
- GitHub API 未认证限流 60 次/小时，很容易用光；用 `api.github.com` 轮询
  状态时要注意。
- Actions job 日志接口（`/actions/jobs/{id}/logs`）需要鉴权，
  公开仓库也拿不到（403 Must have admin rights）。
- 任务摘要只在登录后可见，公开抓不到。

## 补充：用户打不开链接 → 根因是 DNS 缺记录

用户截图显示 `ERR_TIMED_OUT`，打开的是旧地址
`republicans-evanescence-yamaha-favorites.trycloudflare.com`
（那个 run 已被并发控制取消，隧道自然断了）。

**但更重要的发现**：这台机器的 DNS 里 **缺 `raw.githubusercontent.com` 的解析记录**。

| 域名 | PowerShell 解析 |
|---|---|
| github.com | OK |
| api.github.com | OK |
| objects.githubusercontent.com | OK |
| codeload.github.com | OK |
| **raw.githubusercontent.com** | **FAIL（找不到请求的类型的数据）** |

影响：任何用 `raw.githubusercontent.com` 取文件的东西在这台机器上都会失败
（curl 返回 000、Invoke-WebRequest 报「未能解析此远程名称」）。
**要拿仓库文件内容，改用 `api.github.com/repos/{owner}/{repo}/contents/{path}`，
content 字段是 base64，解一下就行。**

这也解释了用户之前说的「网不好进不去 github」——不是 GitHub 挂了，
是 DNS 少了一条记录。

### 交付：公网地址助手
问题根源是「地址每次都变，手抄容易抄到失效的旧链接」。
所以做了个不用手抄的工具：

- `tools/get_tunnel_info.py` —— 三通道自动降级取地址和口令：
  raw.githubusercontent.com → api.github.com → github.com/.../raw/...
  哪个通用哪个。解析时不依赖中文键名（找 `http` 开头的值），
  避免文件格式一变就解析失败。
- `公网地址助手.bat`（项目内，GBK+CRLF）
- `C:\Users\36151\Desktop\公网地址.cmd`（桌面版，写死绝对路径）

桌面版踩的坑：
- `cd /d "%~dp0" "01-项目代码\..."` —— cd 只接受一个参数，会失败
- `cd /d "%~dp001-项目代码\..."` —— 路径含中文时 cmd 需要正确的代码页，
  在 Git Bash 里测试会误判
- **最终方案：cmd 里写死绝对路径 + GBK 编码**，最简单可靠
- 桌面快捷方式（.lnk）要用 COM 创建（WScript.Shell），被安全策略拦了，
  改用 .cmd 文件代替
- `timeout /t 4` 在 Git Bash 里会被当成 Linux 的 timeout，改用 `ping -n 5 127.0.0.1`

## 补充2：固定口令（用户说「我不知道口令呀」）

上一版的随机口令（16 位）虽然安全，但**每次部署都变，用户根本记不住**。
面试演示要的是「我记得这个口令」，不是「口令多难猜」。

### 改动：口令三级优先级
1. 仓库 Secret `ACCESS_PWD` —— 最安全（不在仓库里）
2. **仓库文件 `access-pwd.txt` —— 固定口令，当前用这个，内容 `parking2026`**
3. 自动生成 16 位随机口令 —— 兜底，绝不裸奔

第 2 级新增。读取时清洗首尾空白、引号、CRLF（兼容手写格式）：
```bash
PWD=$(tr -d "\r\n" < access-pwd.txt | sed -e "s/^[[:space:]]*//" -e "s/[[:space:]]*$//" \
      -e "s/^\"//" -e "s/\"$//" -e "s/^'//" -e "s/'$//")
```

### 安全性的实话
仓库本来就是公开的，地址和口令都写在里面（tunnel-info.txt），
**固定口令并不会比随机口令更不安全**。它挡的是「误扫到链接的路人」。

### 实测
固定口令生效：首页 302 → parking2026 登录 302 → 后台 200。
旧随机口令已失效（返回「口令不对」）。
桌面助手 `公网地址.cmd` 也正确显示 parking2026。
